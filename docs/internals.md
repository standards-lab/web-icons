# Internals

This page gives the reasoning behind the repository's configuration, scripts, and sources, which
their `See docs/internals.md` lines point at.

## Tools and tasks (`mise.toml`)

- Tasks never install a missing tool (`task.run_auto_install = false`): `mise run install` is the
  one task that reads the network, and `scripts/preflight.sh` fails a task naming it when a tool
  is missing.
- Chrome for Testing publishes no checksums, so the `chrome-headless-shell` pin's sha256 and size
  are taken from the download by hand at each bump. mise caches downloads by checksum: a version
  bumped without its own sha256 installs the old build, which is why `scripts/preflight.sh browser`
  holds the installed binary to the pinned version.
- The build runs the generator as TypeScript under Node's type stripping, on the installed
  `@iconify-json` sets; tsc then emits the plugin beside the sets. The browse page imports the
  built modules, so the browser tier runs on `dist/`, and the suite's type check reads the
  package's own exports through `dist/`'s declarations.
- `browse`, `screenshots`, and `preview` are never dependencies of `check`: they are a reader's
  and a reviewer's look at the browse page, not tests. The browser tier runs the screenshots
  command and the preview script once each (`test/browser/screenshots.test.ts`).
- `screenshots` runs web-tooling's `web-screenshots` bin over `scripts/screenshots.config.ts`; the
  task's arguments follow it, with or without a leading `--`. Its files go to a fresh directory
  under `TMPDIR` unless `--dir` names one, and `captures/` is gitignored for that. The task is
  `raw`: with dependencies, mise prefixes a task's output through a pipe, and kitty's icat needs
  the terminal.
- `preview` narrows the same capture to the browse page's first wide tile at the default profile,
  light and dark (`scripts/preview.ts`); its images are regenerated by hand and committed.

## Install (`pnpm-workspace.yaml`)

- The repository is one package, so the workspace lists no packages.
- `unrs-resolver`, under eslint-plugin-import-x and eslint-import-resolver-typescript, has a
  postinstall that fetches its native binding when the optional dependency holding it is missing.
  pnpm installs that dependency, so the script isn't run (`allowBuilds`).
- `minimumReleaseAge: 0` turns off pnpm's default wait of a day before it installs a release. The
  currency task moves each pin to its latest release, and that release's notes are read before
  the bump lands, a review that stands in for the age gate; with the wait on, a frozen install of
  a lockfile that pins a release under a day old fails.

## Format (`.prettierignore`)

Prettier formats the code, the JSON, and the stylesheets only: its default run would also rewrite
the Markdown, the YAML, and `pnpm-lock.yaml`. Every file is ignored, then every directory and the
code, JSON, and CSS files are let back in. Prettier also skips what `.gitignore` lists.

## Lint (`eslint.config.js`)

- ESLint never reads `dist/`: the icon modules there are the generator's output, and the layer
  table judges the handwritten sources in `src/`. The suite and the scripts run on node, so they
  take node's globals.
- A CSS module script is recognised by its `type: 'css'` attribute, by the key's name or its quoted
  key. An `import()` whose specifier ends in `.css`, a string or a template whose last part does,
  is refused: a stylesheet is imported statically.
- The layer is an element by its directory, matched from the root (`partialMatch: false`), with a
  second pattern for a file in a directory whose name starts with a dot, which micromatch's `**`
  never enters, so `./.well-known/` and `./..x/` stay in the layer.
- `boundaries/dependencies` defaults to disallow and checks every origin (a package is external)
  and local files no element holds: an import passes only when a policy names its target, the
  layer or a package the table names, which the rule matches by its name, any subpath of it.
  `checkInternals` has it judge an import within the layer too, which the layer's policy allows.
- A declaration file (a handwritten `.d.ts`) has no runtime, so an import that resolves to one
  passes only as a type import, `import type` or `export type`, which tsc erases: the last policy
  refuses any other kind, and as the last whose selector matches it overrides the allow before it.
  The dependency's kind is the declaration's, so `import { type X }` is a value import here, as it
  is to `verbatimModuleSyntax`, which keeps it as `import {}` and so loads the file.
- The boundaries rule judges the file an import resolves to, never the specifier's text, and
  `no-unresolved` fails a specifier that names no file, so no import passes by naming none.
- `no-extraneous-dependencies` judges an import against `package.json`: a package name it doesn't
  declare in `dependencies`, which holds none (a devDependency ships nothing), in every import
  form (`includeTypes`), an internal one among them (`includeInternal`); `no-relative-packages`
  refuses a relative path into another package's files. The package's own name passes there,
  since the manifest has an exports field; `boundaries/dependencies` refuses it, as it resolves to
  `dist/`.
- Every suppression carries its reason: `@eslint-community/eslint-comments/require-description`
  for an ESLint directive, and `@typescript-eslint/ban-ts-comment` at `allow-with-description` for
  a TypeScript one (`architecture/principles/comments.md`).

## Scripts

- `scripts/currency.sh` reads mise's report at the error log level only, since mise warns on every
  run that a GitHub release has no assets. A `github:` devDependency (the foundation, the tooling)
  is pinned to its repository's release tag, which the registry doesn't hold, so it is compared
  with that repository's latest release. `typescript` is held to the newest version
  typescript-eslint's peer range accepts. A peer (vite) is by a caret range, which must admit its
  latest release, so a consumer can install it beside the icons; the range is judged by the
  release rule's own `caretAdmits`.
- `scripts/preview.ts` passes no facet flag, so the capture is the default profile, and no
  `--scheme`, so it is light and dark. A page that fits a single tile has one capture, which
  stands in for its first tile.

## The release rule (`test/unit/release.ts`)

`packInto` in `test/unit/release.ts` sets pnpm's store directory under the pack's destination, in
the environment: unless a store directory is configured, pnpm first probes where its store should
live by writing a short-lived `_tmp_<pid>_<hex>` file into the project, and the browser tier, which
may be running beside the unit tier, checks that the repository's untracked files don't change. The
`--store-dir` flag still probes; pack reads no store, so pnpm never creates it.

## Release workflow (`.github/workflows/release.yml`)

README.md's "Release" gives the steps and why the workflow is dispatched rather than run by the
tag's push. The checkout fetches every branch and tag, so the pack commit's parent and main are
both at hand. The release action releases the tag its `ref` names, not the dispatching ref, main:
it runs `gh release create` on that tag with no target, so the release is the tag fetched and
checked before it.

## The marker fill (`src/vite.ts`)

- The fill runs at `order: "pre"`, on the page as written, before Vite's own transforms read it,
  in dev and at build alike; `ctx.path` is the page's path from the root, `/index.html`, in both.
- A marker's name is `<set>/<name>` and so names no path outside its set's directory. An svg start
  tag holding `data-icon`, however written, must open a marker. An HTML comment's text holds no
  marker.
- Each icon is imported once per plugin, from the module beside the plugin's own.
- The markers are replaced from the last back, so each one's index still points at it.

## The browse page (`browse/`)

- Each glyph's name gets a `<wbr>` after each hyphen, so a line breaks there and only there: a
  hyphen before a digit, as in `accessibility-16`, is otherwise no break opportunity.
- The page's layout: the header's title and selects in a row that wraps, then each set's section,
  its glyphs in a grid of cells as many as the width holds, two to a row at 390px, and never wider
  than the page. A glyph is drawn at 2rem in the text's color, which its markup's `currentColor`
  follows; a name is set small and breaks only at its `<wbr>`s, never within a word. So a cell's
  minimum is its padding and 6.5rem of name: the longest word with its hyphen, `accessibility-`,
  is 14 characters of monospace at 0.75rem, about 6.2rem, and the cell's border is 2px. Three
  cells to a row at 390px would leave each name less than 5rem, so the minimum gives up the third.
- The import map points the foundation's bare specifiers at the installed package's `dist/`, as
  its exports map them; the server answers `/deps/`.
- Each select shows the profile the root carries. The foundation's `preferences.js` applies the
  stored choice there before first paint, and another tab's save on its storage event, so a
  select shows the stored choice and follows another tab's save; with nothing stored it shows a
  profile the URL query, or a capture, set on the root. An attribute absent, or naming a profile
  the page didn't register, shows the facet's default, which the CSS applies with none.
